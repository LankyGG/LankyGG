I'm a cybersecurity engineer in training, currently an **AppSec / DevSecOps apprentice at Capgemini**, working across application security, cloud security, and the emerging discipline of AI/LLM security. My day-to-day involves running and interpreting SAST/SCA scanning (Fortify, Sonatype Nexus IQ) for the AppSec team, and designing secure APIs for generative-AI integrations.

Alongside my apprenticeship, I'm completing a **Mastère Expert Sécurité des Infrastructures & Cloud** (RNCP Level 7) at Guardia Cybersecurity School, and I build my own tooling to go deeper than the day job requires — from a self-hosted DevSecOps metrics platform to a homelab for testing autonomous-agent frameworks locally.

**What I bring:**
- 🛡️ Hands-on AppSec: SAST/DAST/SCA triage, secure code review, vulnerability management at scale
- ☁️ Cloud & IaC across AWS, Azure, GCP — architecture, hardening, and migration
- 🤖 AI/LLM security: secure GenAI API design, LLMOps, prompt/pipeline hardening
- 🏭 OT/industrial security: PLC/SCADA hardening, ISA/IEC 62443 practices
- 🔍 Offensive practice: CTF forensics and web/API challenges on Root-Me

| Attribute | Details |

| **Repository** | [github.com/LankyGG/all-in-one-claude-code](https://github.com/LankyGG/all-in-one-claude-code) |

**Overview:** A rules-and-agents framework that turns Claude Code into a structured multi-agent engineering environment — enforcing code review, TDD, security review, and commit hygiene through composable agents and skills, backed by hooks that gate risky actions in real time.

</details>

<summary><b>🧠 obsidian-vault — LLM-Integrated Personal Knowledge Base</b></summary>
<br/>

A Markdown-based "second brain" combining an Obsidian vault with custom Claude Code commands for ingesting, querying, and linking personal/career knowledge — with strict separation between immutable raw sources and the curated wiki built from them.

| Attribute | Details |
|---|---|
| **Stack** | Obsidian / Markdown, custom Claude Code slash commands (`/ingest`, `/query`, `/save`, `/lint`, `/relier`), wikilink entity graph |
| **Scale** | 400+ tracked files across `wiki/` (entities, concepts, career, cybersecurity, economy domains) and an immutable `raw/` source archive |
| **Performance** | N/A — a retrieval/knowledge system, not throughput-bound |
| **Security** | `raw/` sources are treated as immutable evidence; a contradiction-detection workflow flags conflicting facts across ingested documents instead of silently overwriting them |
| **Impact** | Single source of truth for career history, certifications, and project details — the actual dataset used to personalize this README |
| **Repository** | [github.com/LankyGG/obsidian-vault](https://github.com/LankyGG/obsidian-vault) |

**Overview:** Source documents (PDFs, transcripts, certificates) are ingested once into `raw/`, then distilled into cross-linked `wiki/` entity pages. Each ingest explicitly reconciles new claims against what's already on file, so the vault accumulates a self-correcting, provenance-tracked knowledge graph rather than a pile of disconnected notes.

</details>
